# 配置与命令参考

## 开箱即用推荐配置

大多数用户保持默认值就能直接用：

| 配置项 | 推荐值 |
| --- | --- |
| `default_levels` | `S` |
| `display_timezone` | `Asia/Shanghai` |
| `include_completed` | `true` |
| `fetch_bo_from_details` | `true` |
| `image_theme` | `studio_dark` |
| `image_day_offsets` | `-1,0,1` |
| `enable_daily_push` | `false` |

配置完成后，先直接测试：

```text
/val today
/val s
/val debug
```

## 首次使用步骤

### 1. 先确认基础查询正常

依次测试：

```text
/val today
/val tomorrow
/val debug
```

如果 `/val today` 有返回，就说明主链路已经可用。

### 2. 配置你关注的赛事

如果你不想只按 `S` 级赛事过滤，而是想只看自己关心的联赛，推荐这样做：

1. 先执行：

```text
/val sync_events
```

2. 执行完成后，重载插件，或者至少刷新一次插件配置页。
3. 回到 WebUI，在 `特别关心赛事 special_tournaments` 中多选你关心的赛事。
4. 保存配置并再次重载插件。

常见选择例如：

- `VCT 2026: Americas Stage 1`
- `VCT 2026: China Stage 1`
- `VCT 2026: EMEA Stage 1`
- `VCT 2026: Pacific Stage 1`

配置完成后：

- `/val today` 会优先按特别关心赛事过滤
- `/val s` 也会优先按特别关心赛事渲染图片
- `/val watch` 可以查看当前特别关心赛事
- `/val unwatch 序号或关键词` 可以删除特别关心赛事，不依赖 WebUI 复选框

### 3. 配置特别关心赛事

特别关心赛事会额外触发开赛提醒和赛后战报。

推荐流程：

```text
/val sync_events
/val special_bind
/val special_add VCT 2026: Pacific Stage 1
```

- `/val special_bind` 会把当前群加入特别关心推送目标。
- `/val special` 查看特别关心赛事和推送目标。
- `/val special_del 序号或关键词` 删除特别关心赛事。
- 开赛提醒会在临近预定时间后按配置轮询 VLR 状态；串场比赛提前或顺延时，以 VLR 显示进行中为准。
- 比赛开始时，同一轮扫描到的多场比赛会合并成一条文本提醒。
- 比赛开始后，默认每半小时检查一次赛果；结束后每场比赛单独发送一张战报图。
- `special_map_report_enabled` 默认开启：每张地图打完后每 60 秒检查并立即推送逐图赛果，也可在配置中关闭；Bo1/Bo3/Bo5 全部结束后的总体战报保持原样继续发送。
- 逐图赛果会展示本图比分和十名选手数据；两队本图数据第一的选手使用英雄半身像，其余选手使用英雄头像。
- 战报图包含系列赛比分、每张地图比分、选手英雄与 K/D/A、ACS/ADR、以及一句锐评；锐评会优先结合虎扑赛后帖和 VLR 评论区讨论。
- 高级主题下，开赛提醒图会使用独立的转播台布局，展示大队标、开赛时间、VLR 赛前指数与历史交手。
- 锐评会整合虎扑赛后帖、高亮回复与 VLR 评论区的重复观点，比赛数据只用于避免张冠李戴，不会在文案里堆 Rating/ACS/KDA；AI 输出不符合社区摘要风格时自动回退到本地社区摘要。

### 4. 配置图片展示天数

`image_day_offsets` 控制 `/val s` 展示哪些日期。

示例：

- `0`：只看今天
- `-1,0,1`：昨天、今天、明天
- `0,1,2`：今天、明天、后天
- `-2,-1,0,1,2`：前后共 5 天

注意：

- 最多保留前 7 个偏移值
- 没有比赛的日期也会显示占位块，不会直接消失

### 5. 如果需要每日推送

打开：

- `enable_daily_push = true`

并配置：

| 配置项 | 说明 |
| --- | --- |
| `push_targets` | 每行一个目标 |
| `push_time` | 推送时间，格式 `HH:MM` |

示例：

```text
enable_daily_push = true
push_time = 09:00
push_targets =
aiocqhttp:123456789
```

`push_targets` 支持两种写法：

- 完整的 `unified_msg_origin`
- 简写 `platform_id:group_id`

配置完以后，可以先执行：

```text
/val push_test
```

这样不用等到定时点，也能先验证推送目标和消息发送是否正常。
当前 `push_test` 和每日定时推送会依次发送：

1. 和 `/val s` 相同的近期赛程图
2. 自动判断当前赛事阶段后生成的赛况图：常规赛为小组积分榜，季后赛/淘汰赛为晋级图

如不需要第二张图，可在配置中关闭 `daily_progress_enabled`。

## 指令说明

### `/val today`

查询今天比赛。

特点：

- 默认按 `default_levels` 过滤，默认是 `S`
- 默认包含今天已经结束的比赛
- 如果配置了特别关心赛事，则优先按特别关心赛事过滤

### `/val tomorrow`

查询明天比赛。

### `/val date YYYY-MM-DD`

查询指定日期比赛。

示例：

```text
/val date 2026-04-28
```

### `/val level S`

按等级查询今天比赛。

示例：

```text
/val level S
/val level A
/val level S,A
```

注意：

- 如果已经配置了特别关心赛事，这个命令会先按特别关心赛事筛，再按你手动传入的等级筛

### `/val s`

生成多日赛事图片。

特点：

- 默认展示昨天、今天、明天
- 队伍显示全名和队标
- 右侧显示赛事名、赛事阶段、赛事图标、等级
- 区分已结束 / 进行中 / 未开始三种状态色
- 空白日期会显示占位块

### `/val progress`

自动读取当前特别关心赛事的 VLR 阶段页并生成赛况图。

- 常规赛、Group Stage：显示分组排名、系列赛战绩、地图战绩、回合战绩和净胜回合
- Playoffs、Play-Ins、淘汰赛：显示 Upper/Lower Bracket、各轮对阵、比分、胜者和晋级连接线
- 优先按 `special_tournaments` 的配置顺序选择当前赛事；未配置特别关心赛事时自动选择近期 S 级赛事

### `/val sync_events`

从 VLR 同步可选赛事列表到插件配置。

适用场景：

- 第一次配置特别关心赛事
- 新赛季开始后刷新赛事列表

注意：

- 执行完后，要重载插件，或者刷新插件配置页，WebUI 才能看到新的可选赛事

### `/val watch`

列出当前特别关心赛事。

### `/val unwatch 序号或关键词`

删除特别关心赛事。

示例：

```text
/val unwatch 2
/val unwatch Pacific
```

### `/val special`

列出特别关心赛事、推送目标和开关状态。

### `/val special_add 赛事名`

添加特别关心赛事。

### `/val special_del 序号或关键词`

删除特别关心赛事。

### `/val special_bind`

把当前会话加入特别关心推送目标。建议在目标群里执行。

### `/val special_unbind`

把当前会话从特别关心推送目标移除。

### `/val report`

手动生成最近一场已结束比赛的战报图。

### `/val report_find 关键词`

按关键词手动生成最近一场已结束比赛的战报图。关键词可匹配队名、赛事名或 VLR 比赛 ID。

### `/val push_test`

立即向 `push_targets` 发送赛程图，并在有阶段数据时追加积分榜或淘汰晋级图，用于完整测试定时推送。

适用场景：

- 你刚配置完推送目标
- 你想确认机器人是否真的能发到目标群
- 你不想等到正式推送时间
- 你想确认图片推送是否正常

### `/val debug`

输出当前调试信息，适合排查：

- 当前请求是否成功
- 当前时区是否正确
- 当前是否命中缓存
- 当前默认等级过滤和特别关心赛事是否生效
- 图片命令的日期范围是什么

### `/val monitor`

提示内置控制台入口：AstrBot Dashboard → 插件 → VAL Match → 赛事控制台。
旧的独立 HTTP 前端已移除，不再监听 8765 端口，也不再生成 `status.html`。
监控 JSON 快照仍保留，用于排查后台任务。

## 群内比分竞猜

在赛事控制台“设置”中勾选特别关心赛事，启用竞猜，直接勾选目标群，然后保存。赛事和群均支持多选，无需按 Ctrl。
竞猜采用整场地图比分：BO1 为 1:0 / 0:1；BO3 为 2:0、2:1 及反向比分；BO5 为 3:0、3:1、3:2 及反向比分。
未知赛制、时间或队伍暂不开放。比分不能是平局、负数、超大值或单图回合比分。

群成员必须 @机器人，可以直接说：

- `今日竞猜`：查看今日关注比赛、可竞猜状态和截止时间。
- `竞猜 EDG 2比1 赢 PRX`：按自然语言中队伍顺序填写比分，支持常用简称和一、二、三等中文数字。
- `我觉得 PRX 会以二比一战胜 EDG`：预测 PRX 胜。
- `把 EDG 那场改成 2:0`：覆盖自己此前的预测。
- `改成 2:0`：修改自己最近提交的今日比赛；不明确时会提示补充队名。
- `我猜 EDG 2:1 赢 PRX，FNC 2:0 赢 DRX`：一次提交多场今日竞猜。
- `把 EDG 那场改成 2:0，然后把 FNC 那场改成 1:2`：一次修改多场；也可在同一句里提交新竞猜和修改已有竞猜。
- `@机器人 我的竞猜`：查看自己的姓名、当前积分、各场预测、封盘状态和结算得分。
- `@机器人 积分榜`、`@机器人 竞猜怎么玩`：查看本群排名或玩法。

每个群独立积分，所有成员初始 0 分。猜中胜队得 2 分；同时猜中比分，额外得 3 分，合计 5 分；胜队错误为 0 分。
积分榜同时显示胜负预测正确率：猜中胜队的场数 / 已结算竞猜场数，百分比保留一位小数，并展示命中场数和分母。胜队猜对、比分未完全命中也计为正确；未开始、进行中、封盘待结算的竞猜不计入分母，无已结算竞猜时显示“暂无”。机器人按同样口径统计；现有竞猜记录自动参与计算，无需重新结算。群内查询、定时积分榜和控制台同步展示，排名仍按原有积分规则排列。
同一个人同一场只保留最后一次有效预测。开赛前 10 分钟起不接受提交和修改，等于截止时间也拒绝；提交前会实时核实 VLR 详情，提前 LIVE 也会封盘，顺延不会重新开放已封盘的比赛。
仅支持今日比赛，不开放未来赛程竞猜。批量最多 20 场，各场带上队名和确定的比分，可用逗号、分号、换行或“然后”分开。逐场反馈提交、修改或未保存的原因：一场封盘、比分非法、状态核实失败或队名不明确，不影响其他有效竞猜。批量中的无队名比分不会自动套用最近一场。同一句里重复指向同场比赛时，该场全部拒绝，以免相互覆盖；含“或者”等整体不确定表达时整条不写入。机器人预测不能由群成员修改。

后台每分钟同步比赛和检查定时播报，结束后依据已确认的合法系列赛比分自动结算，重复检查不会重复加分。
修改特别关心赛事后，已有未结算竞猜仍继续检查原赛事。队伍或赛制变更会暂停该场竞猜和结算。
积分榜优先通过 OneBot 同步全群成员；平台不支持时按已见成员展示，并注明其余成员初始为 0 分。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `prediction_enabled` | `false` | 启用群内竞猜 |
| `prediction_bot_enabled` | `false` | 机器人独立参与，同规则计分 |
| `prediction_targets` | 空 | 每行一个群会话，各群独立计分 |
| `prediction_daily_enabled` | `true` | 每日发送今日竞猜 |
| `prediction_after_schedule` | `false` | 同时接收赛程的群，竞猜紧随赛程与赛况发送完成；其他群按竞猜时间发送 |
| `prediction_push_time` | `09:00` | 今日竞猜播报时间 |
| `prediction_rank_enabled` | `true` | 为定时模式的群每日发送积分榜 |
| `prediction_rank_time` | `23:00` | 定时模式的积分榜播报时间 |
| `prediction_rank_after_matches_enabled` | `false` | 启用比赛结束并结算后自动发榜 |
| `prediction_rank_after_matches_targets` | 空 | 选择采用赛后发榜的竞猜群；这些群不再按固定时间发榜 |

时间采用 `display_timezone`。保存设置后立即应用。若重启时已超过当天播报时间，会补发当天尚未成功播报的内容；成功记录持久化，重载后不会重复定时播报。
赛程与竞猜共用逐群持久化发送记录，先完成赛程和可用赛况，再发送该群竞猜。赛程失败不会提前发竞猜；重载可补发尚未成功的任务，各群失败相互独立。
赛后积分榜可在“积分榜播报”中按群选择：等待当天已确认的全部竞猜比赛取得最终赛果、该群竞猜结算完成后，每个比赛日发送一次。无比赛当天不发送；比赛跨过午夜或临时顺延时，继续等待已登记比赛，并在发榜时标注原比赛日。当天比赛清单和成功发送记录持久化，重载后仍可等待或补发失败任务，不会补发启用前的历史榜单。赛程同步失败时不发送尚未核实的赛后榜。所选群以赛后模式替代定时模式，其余群保留原定时开关和时间；手动查榜随时可用。中途从定时切换为赛后模式时，已经发送的定时榜不阻止当天结算后的最终榜。
竞猜持久化在 AstrBot `data/plugin_data/astrbot_plugin_val_match/predictions.sqlite3`，不会因为插件重载而丢失。

开启 `prediction_bot_enabled` 后，机器人确认自己的平台账号，加入各竞猜群积分榜，并在今日竞猜中显示独立预测。模型优先参考已核实的直接交手，并结合双方近期比赛的对手、比分、胜负走势以及当前赛制作判断。没有直接交手时仍预测，明确说明依据较弱；近期比赛资料也缺失时，依据一般赛事理解作低置信度预测，不编造交手、最新阵容、新闻或排名。群成员预测不进入模型输入。

每日竞猜仅展示机器人的预测比分，分析依据保留在控制台。模型公平比较各合法比分，允许横扫，不以资料少为由一律预测接近比分，也不为多样化随机改比分。模型比分经过 BO 校验，生成及提交都必须在封盘前完成；模型服务不可用时展示暂未完成，不伪造模型结果。预测和依据持久化，重载、修改设置和重复播报不会重抽，群成员不能替机器人修改。机器人按相同规则计分，关闭开关后停止新增预测，既有预测仍照常结算。

## 内置赛事控制台

需要 AstrBot 4.28.1 或更新版本。从插件详情页打开“赛事控制台”：

- 赛程时间线：下一场比赛、队标、按开赛时间排列的大时间轴和当前时间标记；用不同颜色区分未开始、进行中、已结束及等待确认。后台任务和事件记录可展开查看。
- 竞猜与积分：今日比赛、封盘状态、按群排名、预测记录、结算和推送事件。
- 设置：可搜索并勾选多个特别关心赛事、直接勾选目标群、机器人参与开关、定时播报和提醒；图片与请求参数放在高级设置中。只保留一份特别关心赛事列表。

控制台支持深浅主题和移动屏幕，所有 API 使用 AstrBot 登录态及官方插件 Page 桥接，不另开服务端口。
“发送今日竞猜”和“发送积分榜”仅发到界面所选的已配置群，可用于测试；“同步比赛”只刷新数据。

## 配置项说明

### 核心配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `default_levels` | `S` | 文本命令默认等级过滤 |
| `special_tournaments` | `[]` | 特别关心赛事，多选，统一用于赛程、竞猜和提醒 |
| `image_theme` | `studio_dark` | Studio 炭黑 / 暖白 (`studio_dark` / `studio_light`)，旧风格仍可选择；逐图赛果保持原版 |
| `image_day_offsets` | `-1,0,1` | `/val s` 的日期范围 |
| `daily_progress_enabled` | `true` | 每日推送和 `/val push_test` 是否追加自动赛况图 |
| `display_timezone` | `Asia/Shanghai` | 输出展示时区 |
| `include_completed` | `true` | 文本查询时是否包含已结束比赛 |

### 请求与缓存

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `request_timeout_seconds` | `10` | HTTP 请求超时秒数 |
| `retry_count` | `2` | 请求失败时的重试次数 |
| `cache_ttl_seconds` | `300` | 赛程、详情和 VLR 评论页缓存秒数 |
| `max_matches_per_message` | `20` | 文本消息最多显示多少场 |
| `fetch_bo_from_details` | `true` | 是否访问详情页补全 BO |
| `max_detail_fetch_matches` | `12` | 一次最多补全多少场 BO |
| `vlr_api_failure_cooldown_seconds` | `600` | 公开 API 超时/失败后的熔断秒数，熔断期间直接走 VLR 网页解析 |

| `daily_progress_enabled` | `true` | 每日推送是否在赛程图后追加积分榜或淘汰晋级图 |
| `special_push_targets` | 空 | 特别关心推送目标 |
| `special_start_notice_enabled` | `true` | 是否发送开赛提醒，提醒会包含文字和小图 |
| `special_report_enabled` | `true` | 是否发送赛后战报 |
| `special_map_report_enabled` | `true` | 是否在特别关心比赛的每张地图结束后立即推送逐图赛果；不影响总体战报 |
| `special_map_check_interval_seconds` | `60` | 开启逐图赛果后的检查间隔，最小 60 秒 |
| `special_result_check_interval_seconds` | `1800` | 开赛后赛果检查间隔 |
| `special_start_poll_interval_seconds` | `300` | 临近开赛时刷新 VLR 状态的间隔；VLR 显示进行中就会触发开赛提醒 |
| `special_start_poll_lookahead_minutes` | `60` | 距离预定开赛多久开始轮询状态，用于串场比赛提前或顺延 |
| `special_match_window_minutes` | `20` | 按预定时间兜底触发时判断开赛提醒的容错窗口 |
| `enable_ai_match_comment` | `true` | 是否尝试用 AI 生成战报锐评 |

## 时间与时区说明

插件默认按 `Asia/Shanghai` 展示时间。

当前时间处理策略：

1. 优先读取 VLR 详情页展示出来的比赛时间
2. 同时读取详情页中的 UTC 时间信息做校验
3. 统一转换到 `display_timezone`
4. 按转换后的日期归类到今天 / 明天 / 昨天

这样做的目的，是尽量避免：

- 代理 IP 所在地区导致网页时间偏掉
- 仅靠网页列表页时间时出现日期归类错误

如果你在中国使用，建议保持：

```text
display_timezone = Asia/Shanghai
```

## 数据源逻辑

插件当前只使用 `VLR`。

实际行为：

1. 先尝试 `vlrggapi.vercel.app`
2. 如果 API 不稳定，回退到 `www.vlr.gg` 页面解析
3. API 失败后默认 600 秒内直接走网页解析，避免连续生成图片时反复等待 API 超时

默认情况下不需要额外配置。

## 排查指南

### `today` 查不到比赛

先检查：

1. 有没有配置 `special_tournaments`
2. 配置的赛事名是不是当前确实有比赛
3. `default_levels` 是否过滤得过严
4. `/val debug` 里“过滤后比赛数量”是多少

### 图片里某一天没有比赛

这是正常的。

现在 `/val s` 会保留空白日期，并显示：

- `此日无关注比赛`

如果你想扩大范围，可以把：

```text
image_day_offsets = -2,-1,0,1,2
```

### 时间不对

先检查：

```text
display_timezone = Asia/Shanghai
```

然后执行：

```text
/val debug
```

确认：

- 展示时区
- 当前插件时间
- VLR 页面时区推断
- VLR 详情时间来源

### `/val sync_events` 之后还是选不到赛事

一般是：

- 还没重载插件
- WebUI 没刷新
- 当前 VLR 页里暂时没有扫到你要的赛事

可以重新执行一次：

```text
/val sync_events
```

然后重载插件，再回到 WebUI 查看。

### 定时推送没发出来

先检查：

1. `enable_daily_push` 是否开启
2. `push_targets` 是否填写正确
3. `push_time` 是否是 `HH:MM`
4. 机器人本身是否有往目标群发消息的权限

然后先执行：

```text
/val push_test
```

如果这个都发不出去，优先先排查目标配置或机器人发信权限。

## Studio 图片风格

新的 `studio_dark` / `studio_light` 使用炭黑、暖白与青柠强调色，统一赛程、全场战报、开赛提醒、赛事积分榜和晋级图。赛程按日期分区，状态与胜队分别高亮；战报突出总比分、地图结果和核心选手数据。图片以 2 倍尺寸绘制后高质量缩小，导出不透明 PNG。缺失队标或头像会显示可识别的文字标记，未知比分显示横线，已确认的 0 分正常展示。

赛事日历采用左右对阵，开赛时间和状态统一放在每张卡片的最左栏，比分位于对阵中央。两侧队标为 88 像素，队名使用固定区域、自动缩小和省略。队标与赛事图标不再添加黑白底块：透明资源保持透明；仅对边缘连通的纯黑白底进行移除。根据背景对比度适配单色标志，保留双色图标内部文字，彩色标志保留原色并在必要时加细轮廓；深色背景中的 Vitality 单色蜜蜂适配为黄色。转换仅用于 Studio 渲染，原始缓存文件保持原样，选手照片和国旗不参与队标变色。

全场战报的两队选手上下排列，正常五人阵容共十行。保留旧版头像、国旗、国家名、英雄图标和名称、Rating、ACS、K/D/A、击杀差、KAST、ADR、HS%、首杀/首死、首杀差、地图选图方、时长以及完整赛后锐评。三张地图为一行，四张为两行两列，五张为三加二的两行布局，均保留所有已完成地图；没有选手照片时沿用数据源占位图或文字标记。

开赛提醒保留双方赔率，并展示青柠 / 蓝色支持率对比条和百分比，左右顺序与上方战队一致。比例来自双方赔率倒数的归一化换算，标注数据来源；双方有效赔率未齐时仅展示已有指数和暂缺说明，不补造支持率。

群内竞猜按明确意图识别：提交或修改自己的比赛比分，以及“今日竞猜”“我的竞猜”“你的竞猜”“积分榜”和竞猜玩法查询。普通冠军预测（如“预测下今年冠军”）、带比分的分析问题和时间文本交给正常聊天处理，不拦截消息、不修改竞猜。明确参与时的非法比分仍会经过原有校验并给出指引。

逐图赛果渲染器不改动，选择 Studio 风格时仍沿用相应的经典高级黑 / 白，输出像素相同。

公开图片样例见 [README](../README.md)。
